# CLAUDE.md

TRIOE: Smart Town Rescue — the 3D version of TRIOE: Mission Mode, a narrative, detective-style IoE learning game. The canonical story/design docs live in the sibling repo `../trioe-lms-mission` (`GAME_CONCEPT.md`, `GUIDE.md`, `CLAUDE.md`). **Read them before writing any story, dialogue, mission, or gameplay-flow content**, and keep new content consistent with them.

This repo's season is **Project Bantay** (`STORYBOARD.md`): six relatable IoT missions around a neighbourhood river-alert network. It replaces the canon's Season One (*Project Beacon*); the sibling repo's `GAME_CONCEPT.md` still describes Beacon until it is updated. Missions 1 (No Signal — Sarah, a 2.4 vs 5 GHz Wi-Fi mismatch) and 2 (The Pump That Won't Quit — Mika, an active-LOW relay) are playable; 3–6 are locked signals.

## Core rules (non-negotiable, from the 2D game)

- No quizzes or multiple-choice tests. Learning is investigation → claim → test → reflection.
- Mission flow is enforced by the XState machine, in order, no skipping: `ENTRY → CALL_FOR_HELP → INVESTIGATION → HYPOTHESIS → CHALLENGE → RESULT → REFLECTION → REWARD`.
- Captain T (the mentor — called "Mr. T" in the 2D canon docs; code ids still say `mr-t`) asks questions; he **never** gives answers, confirms a hypothesis, solves the challenge, or reveals the root cause — not even after success.
- Wrong choices never fail a mission — they redirect (usually Captain T) without punishment.
- Exactly one Insight Gem per mission, only in REWARD, only once (`profile-store.awardGem` guards it).
- Reflection is authored content, shown only after success.
- Characters are scene entities, never portraits in dialogue UI. One shared dialogue cloud in the upper third. Conversation stages stand everyone in one row facing the camera: hero left, help seeker middle, Captain T right (`STAGES` in `world-layout.ts`).
- No spinners or "Loading…" — loading is cinematic ("Responding to a signal…"). Transitions animate.
- The simulated hardware must behave like real hardware ("the System cannot lie").

## Commands

```bash
npm run dev | npm run build | npm run lint
npx tsc --noEmit
```

No test suite. `?debug` in the URL exposes `window.__trioe` (`teleport(x, z)`, `phase()`, `mission()` (machine context: mission id, clues…), `player()`, `session()`, `ambient()` (ambient sound levels)), `window.__trioeThree` (scene, camera) and `window.__trioeBackend` (`webgpu` | `webgl2`) for scripted playthroughs. A hero named `DEV` (any case; `isDevHero` in `profile-store.ts`) opens every playable mission's signal and can answer any of them at any time — no gem needed, none given.

## Maps & doors

There are three maps in one physics world: `junction` (outdoor island at the origin), `clubhouse` (the Circuit Club interior at `CLUBHOUSE.origin`, x=160 — Mission 1 happens here) and `greenhouse` (Mika's greenhouse interior at `GREENHOUSE.origin`, x=-160 — Mission 2; its glass exterior stands southwest of the plaza). `DOORS` in `world-layout.ts` links them (`exitDoorOf(map)` finds an interior's way out); `mission-director.travelThrough()` fades, sets `session.map`, and teleports. Interact points carry a `map`; only the current map's count. Every map stays rendered (they never share the frustum) so the light set never changes. To add an interior: give it a far-away origin, a `MapId`, a door pair, a `LOOKS` entry in `world-canvas.tsx`, an `INTERIORS` camera range in `camera-rig.tsx`, and a warm-up glance there.

**The north bank.** Junction reaches further north than south (walkable `-40 < z < 20`, `TERRAIN.extent.north` / `rimInner.north`, `WORLD_BOUNDS.north`). Past the river, the old north rim is a ridge (`RIDGE`, z −22…−20, with ridge colliders in `terrain.tsx`) with a cutting for the north road; beyond it is a hamlet: Jordan's house (Mission 3's signal), three cottages, the well and benches on its green, a watchtower, an orchard (`ORCHARD`) and a meadow (`MEADOW`). It opens once Mission 2's gem is earned (`isNorthBankOpen` in `missions.ts`; the DEV hero from the start): `north-gate.tsx` closes the cutting with a barrier until then (walking up to it calls `mission-director.nearClosedRoad()`, Captain T's line), and `maybeRevealNorthBank()` plays the one-time reveal (the `north-gate` shot while the barrier lifts) the next time the hero is in Junction, recorded in the profile's `revealed`. While it is closed the minimap clouds it over and villagers don't head up the north road. **To grow the map:** append to the terrain-plan lists, never insert — `getTerrain()` draws the old island's props from a frozen `CORE` box with the paths and walkways wholly south of the ridge, so nothing there moves; the north bank has its own scatter pass and seed.

## Architecture

Next.js 16 (App Router, client-only game via `next/dynamic` ssr:false) · React 19 · React Three Fiber on three.js **WebGPURenderer** (auto-falls back to its WebGL2 backend) · drei · Rapier physics · XState v5 · Zustand · Framer Motion · Tailwind v4. All 3D art is procedural in a WoraWork-style clay diorama look, except the shared character body `public/models/base-character.glb` that most NPCs and heroes wear (Dr Fe, Sarah, Mika and the villagers wear their own low-poly figures, `public/models/dr-fe-chibi.glb`, `sarah.glb`, `mika.glb` and `villager-<id>.glb`; Dr Fe's earlier detailed model `public/models/dr-fe.glb` is kept but unused); all sound is synthesized with WebAudio.

- `src/game/data/` — data-driven content. `types.ts`, `heroes.ts`, `missions.ts` (the season's signals; a mission opens when it is `playable` and the previous gem is earned — `isMissionOpen`, `nextMissionId`; `isNorthBankOpen`), `world-layout.ts` (maps + doors, every shared gameplay position: spawn, clubhouse interior/exterior, the garden, conversation stages, camera shots, interact points, signal positions), `terrain-plan.ts` (river, paths, plaza, bridge, pond, stepping-stone walkways, farm, cottages — `storeys`/`shop` for the two-storey grocery — plaza benches, landmarks, signposts, keep-clear zones), `ambient.ts` (villager models + start points, and `WANDER`: the walkable network — roads, bridge, stepping-stone walkways — built from the terrain plan, the roads meeting on a ring round the plaza (`PLAZA_RING`) rather than at the Junction Node in its centre; set dressing only, never interactable), `mission-script.ts` (the `MissionScript` contract) and one folder per playable mission, `mission-N/`: `dialogues.ts`, `investigation.ts` (clues + evidence surfaces — each surface id is also its interact point, panel and camera shot), `challenge.ts` (editable sketch fields + a pure simulation that behaves like the real hardware and picks the RESULT dialogue), `reflection.ts`, `script.ts` (help seeker, trees, evidence, markers, Captain T's spot per phase, objectives, short lines). `index.ts` registers each folder. New missions = new data folders, not new components.
- `src/game/engine/` — no React. `input.ts` (keyboard/joystick, action events), `sound.ts` (synth; `unlockAudio()` also starts the music), `music.ts` (cozy farm-life background music: a swung G-major tune — pluck arpeggios, bass, ocarina melody, shaker/woodblock, glockenspiel, convolver reverb — scheduled ahead on the audio clock; chords/melody/form are tables at the top), `world-state.ts` (per-frame mutable player/camera state, teleport requests), `terrain.ts` (rasterizes the terrain plan into masks, traces + Chaikin-smooths outlines, merges water colliders, deterministic prop scatter — to keep props off a new building without reshuffling the rest, filter the scatter afterwards like `offGreenhouse`; `groundHeight(x, z)` = the walkable surface's height over the flat y = 0 physics ground (paths/plaza, bridge deck, stepping stones) — the hero, NPCs and villagers are lifted by it, so a new raised walkable surface must be added there; interior floors' tops sit at y = 0).
- `src/game/state/` — no JSX. `mission-phase-machine.ts` (XState machine + singleton `missionActor`; `RESET` takes a mission id), `profile-store.ts` (persisted identity/gems/mute, and `revealed`: unlocked areas whose reveal has played; New Game resets it), `settings-store.ts` (persisted graphics Options: quality preset → max DPR / AO / shadow-map size, shadows, bloom), `session-store.ts` (screen, dialogue, panels, nearby; the current mission's `sketch` being edited and the fields `running` on its device), `use-mission.ts` (reactive hooks; `useDeviceFields(id)` = what a mission's device runs as the world should show it — live while played, fixed once its gem is earned), `mission-director.ts` (**all gameplay rules**, run from the current mission's data: interactions, signals, dialogue flow, evidence, upload, reflection, reward, moving on to the next signal).
- `src/components/world/` — R3F scene. Components read state and call director functions; they never decide outcomes. `terrain.tsx` (extruded land/rim/ridge/paths, water, bridge, pond, colliders), `scenery.tsx` (instanced trees, hedges, daisies, tufts, rocks, lanterns, lilies), `cottage.tsx` (cottages + reusable `TiledRoof`), `landmarks.tsx` (Junction Node, stepping stones, benches, signposts, the north bank's watchtower and well), `north-gate.tsx` (the barrier in the ridge's cutting), `farm.tsx`, `workshop.tsx` (Circuit Club interior, laid out to the club's floor plan — bookshelf, router cabinet, bench and angled diagram board along the back wall; meeting table left, carpet down the middle, sofas and coffee table right, plants in the front corners — plus Mission 1's props: laptop, board, river-alert display, router, ESP32 datasheet poster), `greenhouse.tsx` (Mission 2's glass house outside and its interior room; the outside shows the interior's own `Garden` set through the glass, scaled by `INSIDE` to fit — the exterior is as deep as the interior at that scale — with its water sounds off), `garden.tsx` (Mission 2's set inside it, laid out to Mika's floor plan — two farm areas with instanced crops, a soil sensor and a sprinkler in each, the water tank with the pump in front of it (hoses up the aisle, along the back wall and into each farm), puddles, and the tech area by the door: device table with the tablet, table with plants, sacks, planting tools, and the control box (board + relay) with every cable routed to the sensors, pump, power box and wall plug — the pump follows `pumpRunning()` from the mission's challenge), `character-model.tsx` (every character plays its model's keyframed clips with crossfades), `villagers.tsx` (ambient passers-by who circulate the town: each claims a destination — one of `WANDER`'s end points (doors, the club, the grocery, roads off the map), none shared, chosen away from the others and their destinations so they spread out — walks the shortest way there along the roads (`route`), lingers, sometimes strolls `STROLL_RANGE` onto open grass nearby (`isOpenGround` in terrain.ts), then picks the next; they stop and turn to the hero when close for `GREET` seconds — no gesture — then carry on past, and within `STAGE_CLEAR` of the hero during a conversation they hold still; each moves through a Rapier character controller so it slides along colliders and other villagers, keeps `LANE` right of a road so oncoming ones pass (down the middle of the narrow stepping stones, `laneOf`); a stretch `clearWay` finds obstructed (three waist-high rays against fixed colliders, stopping short of the end so a way may end at a door), or one it is held up on for `STUCK` seconds, is avoided for `AVOID` seconds and the way is re-planned round it), `wildlife.tsx` (ducks, frogs, birds, butterflies — each species is one InstancedMesh per body part driven by a plain simulation object; keep new critters instanced), `materials.ts` (shared canvas-painted textures). `post-effects.tsx` (TSL `RenderPipeline`: GTAO + denoise, bloom, vignette; renders at useFrame priority 1; rebuilt when the AO/bloom settings change). Gotchas: keep `bevelOffset: 0` on terrain extrusions — a negative offset makes three.js smear cap triangles across concave outlines. WebGPU: no GLSL `ShaderMaterial`s (so no drei Sparkles/Environment/postprocessing) — use standard/node materials and TSL; create materials `transparent` up front instead of toggling it at runtime; never change a light's or the fog's constructor `args` or its position in the React tree (a new light id recompiles every material) — update properties in place instead; the AO pre-pass must be single-sampled (`pass(..., { samples: 0 })`). Physics uses `timeStep="vary"` so camera and bodies stay in sync on high-refresh displays (fixed 60 Hz caused judder).
- Characters: every hero and NPC is the plain base model `public/models/base-character.glb` — "©mazko free lowpoly chibi base model" (CC-BY-4.0, credited in `CREDITS.md`; keep that credit) with its own skin material and black outline shell, no per-character design. Built by `blender -b --factory-startup -P scripts/build-base-character.py -- <base model.glb> public/models/base-character.glb`, which normalises height to 1, lowers the T-posed arms close to the sides (80°), shears the splayed legs in so the feet stand close together, adds a Mixamo-style 22-bone skeleton like WoraWork's (Hips > Spine > Spine1 > Spine2 > Neck > Head; Shoulder > Arm > ForeArm > Hand and UpLeg > Leg > Foot > ToeBase per side) with position-based weights so the body and its outline bend identically, and keyframes five clips: Idle, Lookaround, Talk, Walk, Run (key-curve tables in the script; the Walk/Run hips ride on the planted leg so feet meet the ground, and the script prints each gait's stride). `character-model.tsx` hides every model's `solidifyoutline` shell (characters are drawn without a black border; the build scripts still add it, so it can come back by deleting that line) and plays the clips WoraWork-style through an `AnimationMixer` with 0.3 s crossfades (Lookaround after 5 s standing still; Talk while `speaking`); Walk/Run playback speed follows ground speed (`STRIDE` must match the printed strides) up to a cadence cap. Pose angles in the script are about the rest world axes: + pitch swings a limb back / bends a knee / points toes down / leans forward; − pitch bends an elbow. Characters differ only in `height`/`scale` (heroes in `heroes.ts`, help seekers/Captain T in `cast.tsx`, villagers in `ambient.ts`); hero palettes only colour the UI swatches. The clips themselves live in `scripts/character_clips.py` (`bake_all(rig, hip, knee, ankle)` → strides), shared by every build script. Exception: a hero with a `model` in `heroes.ts` wears its own rigged model with the same skeleton and clips. Dr Fe is the "Cute Chibi Girl" body by Syed's Creation (CC-BY-4.0, credited in `CREDITS.md`; keep that credit) dressed as Dr Fe (white hair bun, glasses, black turtleneck, pants, belt, white lab coat), built by `blender -b --factory-startup -P scripts/build-dr-fe.py -- "<Desktop>/DR FE/Dr.FE Model.glb" public/models/dr-fe.glb`: the dense hair, sweater and coat decimated to `DENSE` and textures shrunk to `TEXTURE` (hair keeps only its colour map; the lenses lose transmission), joints measured from that body (head height 1, hair above — so `height` is head height), bone-heat weights on the skin, clothing copying the weights of the skin under it on its own limb (sleeve = cloth within an arm's length of a wrist measured along the cloth — the A-posed hands hang by the waist) and then smoothed, the skin the clothes cover removed, and the clothing the coat hides (it would poke through), the coat's skirt weighted by where it hangs (hips, and part of each thigh's swing towards the hem) so it swings instead of tearing between the legs, head/hair/glasses/shoes rigid, A-pose arms lowered and applied as rest, an inverted-hull outline added; its gait strides are stored as `walk_stride`/`run_stride` extras on the rig node, which `character-model.tsx` uses instead of `STRIDE`. The help seekers Sarah (a schoolgirl after her character sheet: dark teal bob, dark eyes, dark-green gold-trimmed blazer over a white shirt with a buckled collar strap and compass brooch, pleated green skirt with a gold hem line and white frill, brown belt, knee-high boots) and Mika (a girl farmer: straw hat, braids, freckles, and full denim overalls — `bib`: a bib with a pocket and brass buttons, straps crossing into an X on the back, a back panel, denim legs to rolled cuffs over her boots) wear `look.model`s from the villager script below (keys `sarah` and `mika`; `height` in `cast.tsx` is to the top of the hair). The steps the build scripts share (import, normalise, rig, rigid head/shoes, join, arm lowering, outline, bake + export) live in `scripts/chibi_body.py`. (`build-base-character.py` can also build a *dressed* mazko body — the base mesh plus clothing meshes sized to it, no outline mesh: it decimates clothing to `DENSE` vertices, deletes covered skin, grows an outline; trailing `"Material=r,g,b"` args restore colours the glTF exporter drops from colour ramps.)
- Captain T (key `captain-t` → `public/models/captain-t.glb`, `look.model` in `cast.tsx`: a superhero on the boy figure — black hair, a blue long-sleeved spandex top with a white V panel on the chest from the shoulders to a point at the waist (`chest-v`), the navy diamond-T emblem inside it (`emblem`), gold wrist cuffs (`wrist-cuffs`) and a gold belt (`gold-belt`), white tights, yellow knee-high boots and a yellow cape hung from gold shoulder clasps, `cape`), villagers (`ambient.ts`, one model each, named by villager id), the help seekers Sarah and Mika, and the hero Dr Fe (key `dr-fe` → `public/models/dr-fe-chibi.glb`: a scientist all in black — a long-sleeved sweater with loose armholes (`loose`: the top stands off the body along its normals within `ARMHOLE` of each armpit; straight cuffs) tucked into charcoal trousers under a brown belt (`waistband`: a thin band cast round the waist, the top bloused out a little above it; `waist-buckle` at the front) — with dark brown shoes, white hair and round black-framed glasses with clear lenses (`glasses-round`, sized and centred on her eyes; the lens is the see-through `lens-glass` material); the `coat` and `coat-front` pieces build a short white lab coat — one shell over the torso and arms with the skirt extruded from it, set its length with `coat_hem` — but she currently wears none) are built from "Low Poly Characters (PACK)" by micaelsampaio (Sketchfab, CC-BY-4.0, credited in `CREDITS.md`; keep that credit): `blender -b --factory-startup -P scripts/build-pack-villager.py -- <low_poly_characters_pack/scene.gltf> <id> public/models/villager-<id>.glb`. The pack has four flat-shaded T-posed chibis coloured from a palette; the script names each face's part (skin, hair, eyes, brows, beard, shirt, pants, shoes…) from its palette colour and position (`BASES`), repaints the parts in the villager's colours with one flat material per colour, welds the pack's split faces and rounds the figure off with Catmull-Clark (`SUBDIVIDE`: Sarah and Mika two levels, villagers one; smooth shading with creases kept past `SHARP`), brings the splayed legs in so the feet stand close (`FEET_IN`, joints moved with them), thickens the arms about their axis (`ARM_THICK`, eased in from the torso and out over the hands), and adds its accessories (`VILLAGERS`: base figure, paint, extras), then rigs it with `chibi_body.py`'s skeleton on the pack's measured joints (bone-heat weights smoothed `WEIGHT_SMOOTH` passes so shoulders, hips and knees bend without creasing; head rigid), lowers the arms, adds the outline and bakes the shared clips. To restyle a villager or add one, edit `VILLAGERS` and rebuild; accessories that lie on the body (freckles, the bib, the bow) are placed with `front(x, z)`, a ray onto the figure's front. Never change Dr Fe or Sarah through it.
- `src/components/hud/`, `src/components/screens/` — overlays (dialogue cloud, panels, top bar, touch controls, pause menu — Esc with nothing open or the top-bar button: Resume, Options, Main Menu via `leaveToTitle()`; loading/title menu (New Game, Continue, Options)/hero setup). `evidence-panel.tsx` renders any mission's evidence surfaces; on the challenge target the sketch's `{FIELD}` tokens become text boxes or HIGH/LOW toggles (never auto-focused — the E that opens the panel would type into them). A `wiring` tab (`board` data in `types.ts`, drawn by `wiring-board.tsx`) is a hands-on cable board after the Grandpa Boldoo quest in Univision's *Fix-It*: drag a cable's loose end onto a port, or tap the plug and then the port. Guided boards (`steps` + `done`) are numbered Boldoo-style steps, only for checks that are never the answer; probe boards (`readings`, keyed by port `net`) let the player place the `red`/`black` multimeter probes freely. Every reading or `done` goes through `examineEvidence`, so clue dependencies and Captain T still apply. Each mission's hands-on task is in `STORYBOARD.md`.
- `src/components/game-shell.tsx` — screen flow (`loading → title → hero-setup → entering → play`) and the global input → director bridge.
